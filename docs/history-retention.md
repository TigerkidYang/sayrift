# Windows 历史保留与 SQLite 残留处理

本修复仅涉及 `store.py`；不改变控制器、流水线、prompt、Android 或历史界面。

## 保留期限

原实现只在打开数据库或控制器应用设置时调用 `prune()`，长期运行可能继续展示过期文字、计入历史统计，或读取过期录音重试。

现在每次历史及用量的读写都在同一个线程锁和数据库事务内先清理历史，包括列表、搜索、分页、录音读取、统计、重试结果更新、插入、删除以及用量查询和记录。清理提交后才返回结果。保留期限根据当前时钟判断；`stats(today=...)` 和 `spend(today=...)` 的统计日期不改变保留期限。

- `24h`、`1w`、`1m`、`1y` 分别为 1、7、30、365 天；时间戳严格小于截止时间才过期，恰好在边界的记录保留。
- 新增记录本身已经过期时不写入，返回 `None`；重试结果不能让已过期记录重新出现。
- 设置 `keep` 即执行清理。`never` 无条件删除全部历史，包括时钟错误产生的未来记录，并拒绝后续历史写入；`forever` 不做时间清理。
- 显式 `prune(now=0)` 使用 Unix epoch 零时刻，不回落到当前时间。
- 独立 `usage` 表继续保留，不随历史过期或全部删除而清空。

这是访问时执行的保留策略，没有后台定时器：应用不运行或完全不访问存储时，磁盘清理要等下一次访问。已返回给界面的文字、调用方持有的音频和正在进行的重试不会由存储层撤回；系统时钟回拨可能延长仍存在的记录的保留时间。存储实例的 `clock` 参数供离线测试注入时钟，生产默认使用 `time.time`。

## 数据库连接和升级

每个 `History` 连接都明确设置 `PRAGMA secure_delete = ON`，不依赖 SQLite 编译默认值；使用完整 ON 而非 FAST。连接采用 DELETE 日志模式，避免长期保留 WAL 或持久回滚日志中的旧页图像；旧 WAL 数据库由 SQLite 自己切换模式和处理日志，不手动删除文件。内存数据库保持 MEMORY 模式。

数据库版本从 2 升到 3：先保留既有费用补记行为，再执行一次 `VACUUM`，整理旧版本删除后留下的空闲页和有效页内部空隙。迁移也在事务中将历史主键改为 `AUTOINCREMENT`，防止过期清理后复用旧 ID，导致尚未完成的重试误改新记录；已有行的 ID 不变。所有有效行、有效录音和用量行都保留。费用补记与版本 2 标记在同一事务提交；只有 `VACUUM` 成功后才记版本 3。若整理失败，下次打开会重试，不重复补记费用，也不会通过清空数据库来绕过错误。初始化失败会关闭连接并向调用方抛出异常；版本 3 的正常重启及日常删除不重复执行 `VACUUM`，也不降低更高的数据库版本号。

此行为依据 SQLite 的 [secure_delete 文档](https://www.sqlite.org/pragma.html#pragma_secure_delete)和 [VACUUM 文档](https://www.sqlite.org/lang_vacuum.html)。当前存储使用普通表，没有 FTS 等虚拟表。

## 资源和安全边界

- 每次有限保留期限下的访问增加一次使用 `entries_created` 索引的删除操作和事务；多个逐条录音查询也会分别检查。大批过期音频的清理会增加写入、锁持有时间，可能让触发它的界面读取或后台写入暂时变慢。
- `secure_delete=ON` 要覆写删除内容，有额外 CPU 和 I/O。日常删除不收缩文件，已清理页留给后续写入复用，避免每次删除都重建整库。
- 主键迁移需要复制历史表，额外占用数据库空间和回滚日志；`AUTOINCREMENT` 每次插入还需要维护序号。一次性 `VACUUM` 成本随数据库大小增长，可能需要最多约两倍整理前数据库大小的额外可用磁盘空间，并在初始化期间占用写锁。DELETE 模式也牺牲 WAL 的读写并发优势。空间不足或其他连接占锁会让初始化失败，而不是默默宣称迁移完成。
- 只处理当前 SQLite 逻辑文件中已删除内容的可恢复残留，不承诺物理安全擦除。SSD 磨损均衡、文件系统快照、备份、已删除的日志或临时文件、操作系统缓存和进程内存不在保证范围内；事务运行或崩溃恢复期间，回滚日志仍可能包含旧数据。数据库没有因此变成加密存储。
- 以后新增连接、虚拟表或改变日志模式时需要重新审查这些边界；应用之外的工具直接写库不受 `History` 连接设置约束。

## 离线验证

`tests/test_store.py` 使用可推进的假时钟、内存数据库和临时磁盘数据库验证：各保留期限边界、每个读写入口独立触发过期清理、设置切换、未来时间戳、epoch 零时刻、有效数据和用量保留、普通删除及文本更新后文件字节标记消失、旧版空闲页及页内残留升级、WAL 转换，以及迁移失败后重试和连接释放。字节标记检查仅证明测试数据库文件的对应内容消失，不代表介质取证级擦除验证。
