# 手动验收清单

> 当前状态（2026-10-06）：v0.2.1 已正式发布；这里是待执行的验收清单，不是全部通过的结果。发布时自动化与制品核验见 [binary-release.md](binary-release.md)。早期 M1–M3 编号保留作场景分类，视觉预期以当前 Glass 界面为准。

自动化测试覆盖不了真人语音、真实应用和输入法。每个里程碑结束时，把这份清单过一遍，并在 PR 或 commit 里记下结果（✅ / ❌ + 现象）。

启动：`uv run sayrift`（加 `-v` 看调试日志；`run --no-ui` 是没有界面的控制台模式）。日志文件在 `%APPDATA%\local-typeless\logs\app.log`。

## M1：核心听写

**基本交互**（照 Typeless 官方）

| # | 操作 | 预期 |
|---|---|---|
| 1 | 点一下右 Alt，听到“开始”提示音后说一段中文，再点一下右 Alt | 听到“结束”提示音，约 2 s 内整理好的文字出现在光标处 |
| 2 | 按住右 Alt 说话，说完松开 | 同上（按住说话） |
| 3 | 点右 Alt 开始，说几句后按 Esc | 听到“取消”提示音，什么都不插入 |
| 4 | 点右 Alt 开始，不说话，再点一下 | 判定为没有说话，不插入，也不调 API（日志：no speech detected） |
| 5 | 右 Alt + 右 Shift 一起点一下，说中文，再点右 Alt | 插入英文译文 |
| 6 | 选中一段文字，右 Alt + 空格，说“改得正式一点”，再点右 Alt | 选中的文字被替换成正式版本（Ask anything） |
| 6b | 不选中，右 Alt + 空格，说“帮我写一条消息说今晚七点楼下见” | 一条消息被插入到光标处 |
| 6c | 不选中，右 Alt + 空格，问“法国的首都是哪里” | 弹出答案卡片（可复制），文档不变 |
| 6d | 在网页上选中一段英文，右 Alt + 空格，问“这段是什么意思” | 弹出答案卡片，网页内容不变 |
| 7 | 按住右 Alt 时按 Tab（或别的键） | 录音被放弃，Alt+Tab 照常工作 |
| 8 | 单独点右 Alt | 记事本、资源管理器里**不会**激活菜单栏；不影响输入法 |

**不同目标应用**（每个都做一次 #1）

| # | 应用 | 预期 / 注意 |
|---|---|---|
| 9 | 记事本（Win11） | 正常上屏 |
| 10 | 微信 / QQ 输入框 | 正常上屏；风格偏口语 |
| 11 | VS Code 编辑器 | 正常上屏；**确认右 Alt 不会把焦点移到菜单** |
| 12 | Chrome 里的输入框（如 Gmail 正文） | 正常上屏 |
| 13 | Windows Terminal | 使用 Ctrl+Shift+V 粘贴，正常上屏 |
| 14 | 旧式控制台（直接运行 cmd.exe） | 使用控制台自己的粘贴命令，正常上屏 |
| 15 | 以管理员身份运行的程序 | 如果本程序不是管理员：不会上屏，出错提示音，文字留在剪贴板里 |

**剪贴板与输入法**

| # | 操作 | 预期 |
|---|---|---|
| 16 | 先复制一段文字，再听写 | 听写结果上屏后，剪贴板里还是原来那段（Ctrl+V 验证） |
| 17 | 复制一张图片，再听写 | 听写后剪贴板里仍是那张图片 |
| 18 | 连续快速听写两次 | 两次都上屏，最后剪贴板恢复为**听写前**的内容 |
| 19 | Win+V 打开剪贴板历史 | 看不到听写的文字 |
| 20 | 中文输入法处于中文模式时听写 | 正常上屏，不会只出现一个 “v” |
| 21 | 一次说 1 分钟以上（> 200 字） | 完整上屏（有同类项目报过长文本粘贴失败） |

**稳健性**

| # | 操作 | 预期 |
|---|---|---|
| 22 | 断网后听写 | 出错提示音，日志有原因，不卡死；恢复网络后能继续用 |
| 23 | 听写时拔掉 / 切换麦克风 | 出错提示音（“Microphone unavailable”），下次能恢复 |
| 24 | 睡眠唤醒、锁屏解锁后 | 热键仍然有效（钩子每 60 s 自动重装） |
| 25 | 挂着用半天 | 系统键盘没有变卡 |

## M2：界面

| # | 操作 | 预期 |
|---|---|---|
| 26 | 启动 `sayrift`（或双击 `sayrift-gui.exe`） | 托盘出现 Sayrift 图标，没有控制台窗口（gui.exe） |
| 27 | 点右 Alt 开始说话 | 屏幕底部出现 Voice bar，音量条随声音跳动；托盘图标变红；**正在打字的窗口不失去焦点** |
| 28 | 右 Alt + 右 Shift | Voice bar 左侧显示 “→ English” |
| 29 | 结束后 | Voice bar 变成处理中的动画，出字后消失；托盘恢复空闲状态 |
| 30 | 不说话就结束 | Voice bar 显示当前界面语言的静音提示并自动关闭 |
| 30b | 录音时点 Voice bar 上的 ✓ | 等同再按一次右 Alt：结束并插入；**焦点仍在原窗口** |
| 30c | 录音或处理中点 × | 取消，不插入；下一次按右 Alt 能正常开始 |
| 30d | 录音时看 Voice bar 右侧 | 计时器从 0:00 开始走；配置 `[audio] max_seconds = 70` 时，10 s 后变成红色倒计时 |
| 31 | Ask 提问 | 底部弹出答案卡片；点 Copy 可复制；点 Close 关闭；**原来的窗口仍有焦点** |
| 32 | 托盘 → Translate to | 可切换目标语言；下一次翻译使用新语言 |
| 33 | 托盘 → Recent results | 最近 5 条结果，点一下复制 |
| 34 | 托盘 → Launch at login | 勾选后重启电脑，程序自动出现在托盘；取消勾选后不再自启 |
| 35 | 托盘 → Quit | 程序退出，右 Alt 恢复原本的系统行为 |

## 自动化部分（不用手动做）
- `uv run pytest`：单元测试
- `uv run python tools/e2e_dictation.py --translate --ask`：在真实桌面上跑“点按 / 按住 / Esc / 翻译 / 剪贴板恢复 / Ask 替换选区 / Ask 答案卡片”，目标是一个 Tk 测试窗口
- `uv run python tools/bench_polish.py`、`uv run python tools/bench_ask.py`、`uv run tools/bench_asr.py`：模型回归
- `uv run python tools/ui_preview.py`：主窗口各页和首次引导五步的截图（深 / 浅色）
- 安装包：`Setup.exe --silent` 静默安装，`sayrift.exe uninstall --quiet` 静默卸载


## Android 与 v0.2.1 升级验收

以下尚需按实际设备逐项记录；本次文档同步没有执行真机测试。旧小米个人版记录不能代替正式签名 APK 的升级测试。

| 场景 | 预期 |
| --- | --- |
| 首次引导、系统授权后返回 | key、权限状态和引导进度正确恢复；小米后台限制按实际服务状态提示。 |
| 原生 / Compose / 微信输入框，三种模式 | 保留原输入法，结果写入开始说话时的输入框；读不到选区时不执行替换。 |
| 处理中换输入框或应用 | 不写入新输入框，结果卡片可取回文本。 |
| 密码框、不可插入输入框 | 密码框隐藏把手；插入失败显示卡片供主动复制，不自动覆盖剪贴板。 |
| 录音 / 请求中取消、服务被系统停止 | 麦克风停止，失效结果不上屏，下一会话可用；取消不能撤销供应商已产生费用。 |
| 保留期到期、关闭历史、重新打开页面 | 文字历史按设置清理；独立数字用量记录仍保留。 |
| 旧个人 debug 签名安装 | 正式 APK 签名不同，不能直接覆盖；保留旧数据时不要卸载绕过限制。 |
| 正式签名安装后升级、长期待机、旋转屏幕 | 按 [兼容性说明](compatibility.md)验证升级身份、服务恢复与浮层布局，并记录设备 / 系统 / 输入法。 |
