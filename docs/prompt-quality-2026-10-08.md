# 听写提示词改进与评测（2026-10-08）

## 依据与范围

用户授权分析本机历史并针对性改进。只读查看了 Windows 本地 8 条听写记录；短句整体忠实，长段落存在口语分点未充分展开、重复起句残留的问题。样本少，不能据此认定所有场景都存在漏信息或识别错误。没有读取手机历史，也没有重新上传历史录音或原文。

新增用例均为根据问题类型编写的虚构文本，不包含个人历史原文。只修改两端共用的 `dictation.md`；不更换模型、不改 ASR、翻译或 Ask 提示词。

## 改动

- 明确“一件……第二件……”“一个问题……另一个……”也属于分点，浏览器和聊天应用同样适用；保留每项的例子、追问、条件与结尾限制，不改成主题摘要。
- 合并明确放弃并重新开始的名词短语，减少重复铺垫；保留“那个文件，就是昨天那个报价单”这种有意义的补充说明和原语序。
- 明确保留否定、范围、不确定性与条件，不把“可能”“暂时”“如果”“不是说一定”改成确定决定。
- 区分连续事件叙述和步骤清单，避免仅因“先、然后、最后”就插入编号。
- 保留原有问句不回答、请求不执行、提示注入当数据、专有名词、情绪语气和简体转换约束。

评测工具的输出上限从固定 800 token 改为与产品一致的 `max(256, 4 * len(transcript))`，避免长段落被测试工具截断而误判提示词。旧、新提示词都使用这一上限，运行参数均为 4 路并发。

## 对照结果

基线提示词来自 `a31ad09`。每轮为 33 个用例 × 3 次 × 2 个模型：原有 25 条加新增 8 条。新用例覆盖长段非正式分点、中英文两个问题、重复起句、条件与不确定性、纠正时间、普通事件不分点。评测检查模型原始输出，不经过 `pipeline.guard()`。

| 模型 | 基线总通过 | 最终总通过 | 原有 25 条：旧 → 新 | 新增 8 条：旧 → 新 | 总延迟 p50：旧 → 新 |
| --- | --- | --- | --- | --- | --- |
| `deepseek/deepseek-v4.1-flash` | 92/99 | **99/99** | 74/75 → 75/75 | 18/24 → 24/24 | 1.09 s → 1.03 s |
| `openai/gpt-6-luna` | 89/99 | **97/99** | 72/75 → 73/75 | 17/24 → 24/24 | 1.42 s → 1.72 s |

两个模型在基线中都连续 3 次未将中英文“两个问题”排成编号项，最终均通过。第一候选曾让备用模型合并有意义的补充说明，收紧规则后该回退消失。最终备用模型剩下 2 次 `en_shopping_list_notes` 失败：内容保留，但没有转为项目列表；基线同项失败 3 次。原有 25 条检查规则未修改，最终没有新增失败类别。

新增用例在人工复核时修正两类误报：`don't` / `Don't` / 弯引号不影响约束含义；只保留一次表示“例如”的“之类的”不等于重复赘词。使用最终相同规则重算基线、中间候选和最终候选的已保存输出，未为重新计分重复调用 API。

三个完整批次共 594 次文本请求，无请求错误；服务返回的总成本约 **$0.079**（基线 $0.021877、中间候选 $0.026345、最终 $0.030736）。价格、缓存、供应商和延迟会变化，不应把此次小样本延迟差当作稳定加速。API 原始结果保留在本地忽略的 `bench-polish-*.json`，不提交私人历史或评测原始输出。

人工复核了长段落、重复起句、限定条件、指代补充等输出。自动检查不能证明任意输入都不会丢信息；没有测音频识别准确率或真人端到端体验。原长历史的分点问题在虚构长样例基线中未稳定复现，因此改善证据主要来自稳定失败的非正式两个问题、事件误分点及边界回归，不把所有长段都算作已修复。

## 复跑与两端验证

```powershell
uv run python tools/bench_polish.py --models deepseek/deepseek-v4.1-flash openai/gpt-6-luna --repeat 3 --workers 4 --out bench-polish-check.json
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

真实评测使用 `OPENROUTER_API_KEY` 并产生费用；若当前终端未继承用户环境变量，可重新打开终端，或仅在该进程读取用户环境变量，不打印或落盘密钥。

最终源码验证：Python **185/185**、Android core **19/19** 通过，Ruff lint / format、文档本地链接与 Git diff 检查通过。Android 构建后的 `dictation.md` 与桌面源文件逐字节一致（SHA-256 前缀 `4e066b1045bd2f46`）。

Android `:core:test` 验证共享提示词的构建加载和流水线。Windows 上如 Gradle 报 `Unable to establish loopback connection`，可为本次命令设置较短的 TEMP / TMP 路径后重试，不需要改产品代码。

本次为源码改动，已发布的 v0.2.1 EXE / APK 不会自动获得新提示词；需要从更新后的源码运行，或重新构建安装包 / APK 后才生效。
